TARTEMETER v2.6.1

COMBAT PERFORMANCE
- Replaced per-hit target scans with coalesced damage batches.
- Up to 512 damage callbacks share one transient game-thread monster snapshot.
- Large backlogs continue in 4 ms slices instead of one long blocking pass.
- Exactly one ExecuteWithDelay and ExecuteInGameThread job is created per batch,
  not one pair of jobs for every damage number.
- A 5,000-hit simulated burst completed in ten world snapshots.
- Hit totals, critical hits, highest hit, timeline events, and exports are still
  recorded individually.

TARGET AND OWNER RESOLUTION
- HitLocation matching is performed against a single shared snapshot per batch.
- Each matched target resolves LastAttacker only once per batch.
- Chako remains a separate damage row and is resolved by DsMon_Chaco_V2_C.
- Normal target LastAttacker still has priority over explicit source ownership.
- Explicit source matching now runs only when target ownership is unresolved.
- Owner-chain traversal is capped at 18 nodes.
- Unresolved owner chains use a short 250 ms negative cache.
- Owner caches are pruned every second.

SOURCE OWNERSHIP
- Replaced the duplicate-prone source array with a keyed source-record map.
- Repeated overlap callbacks refresh the existing record in constant time.
- Source records are pruned every 500 ms and capped at 512 entries.
- Equal-time candidates use a deterministic newest-record tie break.
- Tarte's longer orb continuation windows and all existing source reuse limits
  are preserved.

GAME-THREAD AND FILE-I/O LOAD
- Removed immediate FindAllOf from ClientShowDamageText.
- FindAllOf("DsMonsterCharacter") now exists in one batch-snapshot function only.
- High-frequency DAMAGE, DAMAGE_PENDING, SOURCE_ACCEPTED, and SOURCE_REJECTED
  strings are not formatted when verbose logging is disabled.
- Timeline disk writes were removed from the per-hit callback.
- Timeline data is flushed by the background maintenance loop in larger batches.
- Large battle JSON event arrays are assembled in 256-event chunks to reduce
  temporary allocations during automatic raid export.

MEMORY AND CRASH HARDENING
- No Unreal UObject is retained in pending damage, source, owner, or timeline data.
- Every monster/attacker UObject remains local to one game-thread callback.
- Pending damage is bounded and invalidated by combat-generation tokens on RESET
  and map travel.
- Source records, owner caches, Chako diagnostics, target grace entries, timeline
  buffers, and battle events all have explicit reset, prune, or size limits.
- Hook callbacks remain protected with pcall.
- Exactly two established UE4SS combat hooks remain enabled.

FALSE TARGET FILTER
- Damage text whose nearest target is Chako or the observed Kalien allied fox
  classes is ignored as damage received by an allied summon.
- Allied summon actors remain valid attackers and can still receive attribution
  as the source of damage against an enemy.

PRESERVED FUNCTIONALITY
- Total damage, DPS, hit count, critical-hit count and rate, highest hit, average
  hit, damage share, target display, character colors, and Chako's separate row.
- Automatic raid/encounter save before reset.
- Manual RESET save protection.
- Battle history, latest JSON/CSV, current timeline, and LOGS timeline.
- Adjustable lower LOGS panel.
- Themes, opacity, text scale, always-on-top, click-through, configurable hotkeys,
  show/hide behavior, installer, update, launch, and optional UE4SS removal.

RUNTIME NOTE
- Static and simulated tests cannot guarantee that a native game or UE4SS fault
  is impossible. A new native crash still requires CrashContext.runtime-xml and
  the corresponding dump.
